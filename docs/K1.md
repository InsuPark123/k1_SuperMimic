# K1 Rev.1 support

The default remains Unitree G1. Set `SUPERMIMIC_ROBOT=k1` on **every** data
conversion, training, evaluation, and playback command to select K1. Robot
selection is fixed when Python starts; use separate processes for G1 and K1.

Initialize the official asset submodule after cloning:

```bash
git submodule update --init --recursive
```

K1 uses the pinned `third_party/ai_sapiens` MJCF and its meshes. Its mjlab
asset configuration in `src/supermimic/envs/k1_config.py` is adapted from
ROBOTIS Cyclo MJLab, under the Apache 2.0 license in
`third_party_licenses/ROBOTIS-APACHE-2.0.txt`.

K1 input CSV rows contain root position (metres), root quaternion (xyzw), and
23 K1 joint positions (radians), in MJCF joint order. A matching named header
is optional. This is not the 29-joint G1 format. Convert a K1 motion at its
actual frame rate; for example, the Taeguek files used by `robotis_mujoco` have
50 Hz playback according to their `sim2real.yaml` and reference loader:

```bash
SUPERMIMIC_ROBOT=k1 uv run python scripts/data/csv_to_npz_batch.py \
  --input-dir /home/hc/robotis_mujoco/policy/Mimic/taeguek_complete/taeguek_01/params \
  --pattern taeguek_1.csv --input-fps 50 --workers 1 \
  --output-dir data/npz/k1_taeguek
```

Training uses the existing `sm-train` CLI with K1 NPZ inputs:

```bash
SUPERMIMIC_ROBOT=k1 uv run sm-train --run-name k1_taeguek \
  --data.npz-dir data/npz/k1_taeguek --env.num-envs 256 \
  --policy-trainer.batch-size 256 --schedule.max-hours 1
```

This is an example for a short simulation experiment, not a proven training
recipe. Checkpoint files identify their robot, so a G1 checkpoint cannot be
loaded in K1 mode. Confirm the selected MJCF version and motion quality before
training; successful simulation alone does not establish physical-robot readiness.
