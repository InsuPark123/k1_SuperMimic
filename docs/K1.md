# K1 Rev.1 support

The default remains Unitree G1. Set `SUPERMIMIC_ROBOT=k1` on **every** data
conversion, training, evaluation, and playback command to select K1. Robot
selection is fixed when Python starts; use separate processes for G1 and K1.

Initialize the official asset submodule after cloning:

```bash
git submodule update --init --recursive
```

K1 uses the pinned `third_party/ai_sapiens` MJCF and its meshes. Its mjlab
asset configuration in `src/supermimic/envs/k1_config.py` is adapted from
ROBOTIS Cyclo MJLab, under the Apache 2.0 license in
`third_party_licenses/ROBOTIS-APACHE-2.0.txt`.

K1 input CSV rows contain root position (metres), root quaternion (xyzw), and
23 K1 joint positions (radians), in MJCF joint order. A matching named header
is optional. This is not the 29-joint G1 format. Convert a K1 motion at its
actual frame rate; for example, the Taeguek files used by `robotis_mujoco` have
50 Hz playback according to their `sim2real.yaml` and reference loader:

```bash
SUPERMIMIC_ROBOT=k1 uv run python scripts/data/csv_to_npz_batch.py \
  --input-dir /home/hc/robotis_mujoco/policy/Mimic/taeguek_complete/taeguek_01/params \
  --pattern taeguek_1.csv --input-fps 50 --workers 1 \
  --output-dir data/npz/k1_taeguek
```

Training uses the existing `sm-train` CLI with K1 NPZ inputs:

New K1 runs default to per-joint encoder bias uniformly sampled at each episode
reset: `[-0.07, 0.07]` radians for the twelve leg joints and `[-0.01, 0.01]`
for all other joints. The world-model context uses the corresponding per-joint
normalization. IMU pitch offset is disabled by default.
For orientation-bias training, `--env.imu-pitch-offset-deg 5` and
`--env.imu-roll-offset-deg 3` independently sample symmetric offsets in
degrees per episode. A fixed pelvis-local rotation vector (roll, pitch, 0)
is applied to the pelvis and torso orientation observations; the same bias is
held for each imagined rollout. This models observation error, not a change to
the physical pose or a gyro bias. The local-rotation convention matches the
sim2sim IMU-offset experiments.
The K1 system-ID DR profile is enabled by default for new training runs. It
adds independently randomized PD gains (0.9–1.1) and motor output and torque-cap
scaling (0.9–1.0). By default joint friction uses the model's nominal values and
the randomized motor command delay is disabled. Use `--env.motor-delay-dr` to
enable the shared per-environment 0–4 physics-step (0–20 ms) command delay
without randomizing joint friction. By default the world-model and critic context has 27
values: foot friction, 23 encoder offsets, and three torso COM offsets. The
other randomized parameters still affect the simulation, but are hidden from
the model and critic. For the previous experiment with randomized leg friction
and per-episode 0–4 physics-step command delay, use
`--env.k1-legacy-friction-delay-dr`. Use it together with
`--env.extended-dr-context` for the earlier 132-value context, which also
includes these physical values, the delay and the previous command. Its
substep effects remain an approximation learned from simulation.
To match older K1 runs, use `--env.encoder-bias-range 0.01` and
`--env.no-k1-system-id-dr`. Resuming a checkpoint with a different bias
normalization or context layout is rejected; start a new run or supply the
checkpoint's original settings, including `--env.k1-legacy-friction-delay-dr`
and `--env.extended-dr-context` for 132-value checkpoints. Older 27-value
checkpoints can load with the new defaults, but their training DR differs;
set `--env.k1-legacy-friction-delay-dr` to retain the earlier DR on resume.

```bash
SUPERMIMIC_ROBOT=k1 uv run sm-train --run-name k1_taeguek \
  --data.npz-dir data/npz/k1_taeguek --env.num-envs 256 \
  --policy-trainer.batch-size 256 --schedule.max-hours 1
```

This is an example for a short simulation experiment, not a proven training
recipe. Checkpoint files identify their robot, so a G1 checkpoint cannot be
loaded in K1 mode. Confirm the selected MJCF version and motion quality before
training; successful simulation alone does not establish physical-robot readiness.

## Optional XY and yaw tracking

The original reward already tracks global torso position and orientation, but
the standard actor has no direct reference-relative pose observation. For a
new experiment, add explicit pelvis XY and yaw rewards and provide the actor
with reference-relative torso position and orientation:

```bash
SUPERMIMIC_ROBOT=k1 uv run sm-train --run-name k1_taeguek_xy_yaw \
  --data.npz-dir data/npz/k1_taeguek --env.num-envs 256 \
  --policy-trainer.batch-size 256 --env.anchor-obs \
  --env.base-xy-weight 1.0 --env.base-yaw-weight 1.0 \
  --env.base-xy-std 0.3 --env.base-yaw-std 0.4 \
  --schedule.checkpoint-interval 1000 --schedule.max-hours 1
```

XY error is measured in metres and yaw error in radians (wrapped at ±π).
Each new reward is `weight * exp(-error_squared / std_squared)` before the
environment time-step scaling. These initial weights are experimental. The
simulator and imagined reward use the same terms. The reference-relative pose
observation changes the policy input size, so start a new run rather than
resuming a checkpoint trained without `--env.anchor-obs`. For hardware, that
observation requires a suitable estimate of the robot and reference poses in
the same coordinate frame; simulator ground truth is not available by default.

## Orientation-only experiment (no robot-relative position input)

Use `--env.anchor-ori-obs` for a new K1 run. This keeps the six-dimensional
reference-relative torso orientation but omits all three reference-relative
torso position values from the actor's goal. With ten future frames, the goal
is 566 values; the proprioception history remains 750 values. `--env.anchor-obs`
is the old 569-value full-pose mode and cannot be combined with this option.

```bash
env -u PYTHONPATH SUPERMIMIC_ROBOT=k1 uv run sm-train \
  --run-name k1_taeguek_ori_only --data.npz-dir data/npz/k1_taeguek \
  --env.num-envs 4096 --policy-trainer.batch-size 4096 \
  --env.anchor-ori-obs --env.base-xy-weight 1.0 --env.base-yaw-weight 1.0 \
  --env.base-xy-std 0.3 --env.base-yaw-std 0.4 \
  --schedule.checkpoint-interval 1000 --schedule.max-hours 2
```

This starts a new policy; an old 569-value checkpoint cannot be resumed into
the 566-value network. The XY reward still uses simulated ground truth during
training; it is not an actor observation. The orientation input still requires
a reliable torso attitude and initial reference-heading alignment at runtime;
IMU heading drift and transitions need testing. The generated export remains a
research draft. The robotis_mujoco adapter supports the 566-value mode for
simulation; this is not a physical-robot runtime.

## Experimental IMU pitch-offset training

Add `--env.imu-pitch-offset-deg 6` to a new training run to sample a fixed
pelvis-frame orientation offset uniformly from -6 to +6 degrees per episode.
It changes projected gravity and the reference-relative torso pose observation,
including the pelvis-to-torso rotation; it does not change the physical pose or
gyro. Imagined trajectories independently sample from the same distribution and
keep the offset fixed across the history and rollout. The default is zero.

This reproduces an orientation-output bias, not a complete IMU mounting-error
model. A robust simulation policy is not evidence of real-world safety.

```bash
env -u PYTHONPATH SUPERMIMIC_ROBOT=k1 uv run sm-train \
  --run-name k1_taeguek_pitch_dr --data.npz-dir data/npz/k1_taeguek \
  --env.num-envs 4096 --policy-trainer.batch-size 4096 \
  --env.anchor-ori-obs --env.imu-pitch-offset-deg 6 \
  --env.base-xy-weight 1.0 --env.base-yaw-weight 1.0 \
  --schedule.checkpoint-interval 1000 --schedule.max-hours 2
```

## Automatic research export

On K1 training startup, `logs/<run>/params/` automatically receives a draft
`sim2real.yaml`, CSV motion files, exact source NPZ snapshots, and hashes.
When a K1 checkpoint is opened with `scripts/play.py` or evaluated with
`scripts/eval_benchmark.py`, `logs/<run>/exported/policy.onnx` is generated
automatically. Checkpoint-specific copies are retained in `exported/checkpoints/`.
To export without opening a viewer:

```bash
SUPERMIMIC_ROBOT=k1 uv run python scripts/play.py \
  --ckpt logs/k1_taeguek_xy_yaw/ckpt_latest.pt \
  --npz-dir data/npz/k1_taeguek --device cpu --export-only
```

**Research draft only: not compatible with the stock robot runtime.** The YAML
intentionally declares unregistered SuperMimic observation terms. The runtime
still needs an adapter for the 10-frame observation history, future reference
features and reference-relative torso pose. The latter requires a validated
real-world pose estimate. CSV alone does not include the NPZ reference
velocities required to reproduce the actor input. Before any robot operation,
the complete runtime and observation interface must be verified in Sim2Sim.
